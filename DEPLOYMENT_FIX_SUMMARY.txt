================================================================================
PROBLEM OVERVIEW
================================================================================

The project was failing to deploy on Hetzner servers (both Debian and Rocky 
Linux) via Coolify, despite building successfully on local MacOS environment.

Initial Symptoms:
- Build completed locally without issues
- Server deployments failed with NEXT_EXPORT_ERROR
- Error: "<Html> should not be imported outside of pages/_document"
- Multiple pages failing static generation during build
- 404/500 error page generation failures

The project was working fine until yesterday when changes broke deployment.

================================================================================
ROOT CAUSES IDENTIFIED
================================================================================

1. CUSTOM ERROR PAGES ISSUE
   - Created custom error.tsx, global-error.tsx, and not-found.tsx
   - These files used raw <html> and <body> tags
   - Caused Next.js to throw "<Html> import" errors
   - Conflicted with App Router document structure

2. BUILD METHOD INCOMPATIBILITY
   - Original: Using PayloadCMS server-based build approach
   - Command: "NEXT_BUILD=true node dist/server.js"
   - This method was forcing static export mode
   - Triggered NEXT_EXPORT_ERROR for all dynamic pages

3. NODE.JS VERSION MISMATCH
   - PayloadCMS requires Node.js 20+ for undici package
   - Dockerfile was using Node.js 18.8
   - Caused: "File API not available" errors

4. NPM DEPENDENCY CONFLICTS
   - Updated @types/node from 18 to 20
   - Conflicted with @payloadcms/eslint-config peer dependencies
   - Required: legacy-peer-deps flag

5. STATIC GENERATION ISSUES
   - Many pages tried to statically generate during build
   - Pages with authentication, useSearchParams, React Context failed
   - Needed explicit dynamic rendering configuration

================================================================================
SOLUTIONS IMPLEMENTED
================================================================================

✅ 1. REMOVED CUSTOM ERROR PAGES (Critical Fix)
   - Deleted: src/app/error.tsx
   - Deleted: src/app/global-error.tsx  
   - Deleted: src/app/not-found.tsx
   - Let Next.js handle error pages natively
   - Eliminated all <Html> import errors

✅ 2. CHANGED BUILD METHOD (Critical Fix)
   Before:
   "build:next": "cross-env PAYLOAD_CONFIG_PATH=dist/payload/payload.config.js 
                 NEXT_BUILD=true node dist/server.js"
   
   After:
   "build:next": "cross-env PAYLOAD_CONFIG_PATH=dist/payload/payload.config.js 
                 NODE_ENV=production next build"
   
   Result: Direct Next.js build, no forced static export

✅ 3. UPGRADED NODE.JS VERSION
   - Dockerfile: FROM node:18.8-alpine → FROM node:20-alpine
   - Added .node-version file with "20"
   - Added engines in package.json: "node": ">=20.0.0"
   - Kept @types/node at 18.11.3 for PayloadCMS compatibility

✅ 4. FIXED NPM DEPENDENCIES
   - Created .npmrc with: legacy-peer-deps=true
   - Updated Dockerfile npm install: --legacy-peer-deps flag
   - Resolved @payloadcms/eslint-config conflicts

✅ 5. ADDED DYNAMIC RENDERING CONFIGS
   Root Level (src/app/layout.tsx):
   - export const dynamic = 'force-dynamic'
   - export const revalidate = 0
   - export const dynamicParams = true
   - export const fetchCache = 'force-no-store'

   Individual Pages (added to 20+ pages):
   - /account/* (all account pages)
   - /cart, /checkout
   - /login, /create-account, /reset-password, /recover-password, /logout
   - /orders/*
   - /products, /products/[slug]
   - /styleguide/* (all styleguide pages)
   - /terms-and-conditions
   - Home page (src/app/page.tsx)

✅ 6. NEXT.JS CONFIG OPTIMIZATIONS
   Added to next.config.js:
   - output: 'standalone' (Docker/server mode)
   - experimental.isrMemoryCacheSize: 0 (disable ISR)
   - experimental.esmExternals: false
   - experimental.serverComponentsExternalPackages: []

✅ 7. FIXED NULL MEDIA HANDLING
   - CategoryCard: Added null check for media?.url
   - Footer: Skip rendering icons without URLs
   - Added fallback background colors

================================================================================
TROUBLESHOOTING GUIDE
================================================================================

If Build Fails with "<Html> import error":
→ Ensure custom error pages are deleted
→ Check for any remaining imports from 'next/document'

If Build Fails with "NEXT_EXPORT_ERROR":
→ Verify next.config.js has output: 'standalone'
→ Ensure dynamic configs are in layout.tsx
→ Check build:next script uses "next build" directly

If Build Fails with "File API" or "undici" error:
→ Verify Dockerfile uses node:20-alpine
→ Check .node-version file exists with "20"

If Build Fails with npm dependency conflicts:
→ Ensure .npmrc has legacy-peer-deps=true
→ Clear npm cache: npm cache clean --force
→ Delete node_modules and reinstall

If Build Succeeds Locally but Fails on Server:
→ Check server has Node.js 20 installed
→ Verify environment variables are set correctly
→ Ensure database connection is working
→ Check server has sufficient memory (recommend 8GB+)

If Pages Show "Cannot read properties of null":
→ Check for null media object handling
→ Verify all context providers have default values
→ Ensure useContext hooks check for undefined

================================================================================
RESOURCE RECOMMENDATIONS
================================================================================

Current Server: 3.5GB RAM
Recommended: 8GB+ RAM for smoother builds and operations

Reason: PayloadCMS + Next.js builds are memory-intensive:
- Static page generation loads all pages into memory
- Image optimization requires significant RAM
- TypeScript compilation needs resources
- Docker builds add overhead

Alternative Approaches if Memory is Limited:
1. Build locally, deploy static assets
2. Use CI/CD pipeline with larger build machine
3. Switch to platforms like Vercel, Railway, or Render
4. Enable swap space on server (temporary solution)
